## 04. Core Design Rules

### 3D

3D must have a reason.

Do NOT use:

- random cubes
- random spheres
- generic planets
- spinning Earth
- floating laptops
- astronauts
- robots
- decorative shapes
- generic downloaded 3D models
- excessive particles

Preferred visual language:

**one custom technical core / network system**

It can represent relationships between:

- Software
- AI / ML
- IoT
- Cloud
- Networking
- Cybersecurity
- Creative Technology

Prefer custom procedural geometry, lines, nodes and connections.

Use 3D selectively:

- Hero: subtle
- Playground: primary interactive 3D
- Projects: minimal
- Triple I: photography-focused
- Certificates: no unnecessary 3D
- Field Notes: photography-focused
- Build Log: optional subtle technical visual
- Closing: optional return of the core

The website must still work visually without WebGL.

### Motion

Use Framer Motion for:

- text reveals
- image masks
- staggered entrances
- subtle parallax
- project transitions
- navigation transitions
- layout transitions
- hover states

Avoid:

- excessive bouncing
- constant movement
- random glitches
- unnecessary rotations
- flashy particle effects
- animations that slow navigation

Motion should feel:

**cinematic, smooth, controlled and expensive.**

### Interaction

Use a subtle custom cursor with contextual states:

- normal
- VIEW
- READ
- OPEN
- EXPLORE
- OPEN ↗

Do not make it distracting.

Respect reduced-motion preferences.
